可确认该实验配置为单通道、21 层/21 张，返回的进度索引未达到末尾，查询时已不在运行。**索引不直接等于完整落盘张数**，也不应据此断言“已保存 7 张”或“完成 8 层”。

如果目标是完整 Z-stack，应先核对 ZEN 中该实验手动执行时长与输出，再设置覆盖实际时长的截止时间。如果目标是单平面 mark，则需要在 ZEN 中准备独立单层实验，不能直接将本轮 21 层配置用于正式 mark 单平面流程。

### 4.3 上 mark 完成记录

用户确认目录 `mark_affbf1b99a0345c98dbfb178adc24622` 中存在 `upper.tif` 和 `capture.json`。提供的状态如下：

```json
{
  "state": "complete",
  "result_valid": false,
  "recovery_required": false,
  "started_at": "2026-11-13T02:27:05.768+00:00",
  "updated_at": "2026-11-13T02:27:15.965+00:00",
  "kind": "mark_capture",
  "failure_stage": "",
  "pair_complete": false
}
```

相应光学位置记录：

```json
{
  "optics_positions": [null, null],
  "optics_verified": [false, false]
}
```

解释：

- `complete` 和文件存在支持本轮单层采图流程完成，耗时约 10.2 秒。
- `pair_complete: false` 对仅拍上 mark 是正常结果，不是本轮单层失败。
- `recovery_required: false` 表示本轮完成后没有新增待确认状态，不能自动替其他历史轮次解除恢复锁。
- 当前 V2.4.0 的 `MarkRecords.status()` 对 mark 固定写入 `result_valid: false`，所以这个字段在本实现中不能用来判定 TIFF 是否保存成功；详见 [zen_marks.py](../../zen_marks.py)。
- 两项位置为 `null` 表示无法自动读取，不代表物镜/倍率为零、没有硬件或已经锁定。
- 本轮没有提供完整 `recipe`、`images.upper` 或全部 RPC trace；不能仅凭此片段确认 `capture_kind`、`use_autofocus`、实际 Z、像素标定及图像内容。此前建议关闭局部 AF，但完整成功配方仍需补充确认。

## 5. 发现的问题与改进建议

本节为待办建议，本次上传不改变程序行为、不发布新版安装包。

| 问题 | 现场影响 | 建议 |
| --- | --- | --- |
| 读取光学位置的聚合报告显示 `success`，但两个 RPC 不支持 | 容易被理解为位置已成功核验 | 增加“接口不支持/位置未校验”的明确展示，区分检查完成与能力可用 |
| mark 完成后仍显示 `result_valid: false` | 用户无法判断采图是否成功 | 分开表达单层保存成功、图片对完整、业务分析结果有效；保留必要的记录兼容说明 |
| 实验 ID、会话 ID 都是长字符串 | 用户将 session_id 误填到 experiment_id，触发参数错误 | 在界面更明确显示 Load 返回 ID 及生命周期，并提醒会话 ID 不是实验 ID |
| 两层人工确认/恢复锁含义难区分 | 请求可能在本地被拦，用户误认为 ZEN 失败 | 显示本次动作确认与历史待确认记录的不同来源；明确是否实际发出 RPC |
| 本次请求 `recovery_required: false` 时仍可能存在历史锁 | 状态易误读 | 展示全局待确认数量/原因，避免将本次标志当作全局状态 |
| `INVALID_ARGUMENT` / `ALREADY_EXISTS` 仅有通用提示 | 不便定位参数和输出名冲突 | 增加有条件的排查提示，采集默认提供唯一输出名；不得武断认定具体冲突原因 |
| 60 秒默认超时不足以覆盖本轮多层扫描 | 超时后需要额外查询与现场确认 | 明确单层与多层实验区别，按真实采集时长配置；不能通过超时取消推断设备停止 |
| 多个新版方法现场未实现 | 标准流程因某一能力缺失失败 | 形成按方法记录的能力矩阵；针对现场版本做有依据的适配，不静默换单位或成像方式 |
| AF 参数读取不支持 | 当前局部 AF 流程不能运行 | 继续明确提供无 AF 手动示教采图；执行 AF 是否支持需另行安全验证，不能由参数接口失败推断 |
| 无转盘/倍率位置读取 | 无法自动核验光路变化 | 持续明确“未校验”，保留现场检查；读取 Z 或采图成功都不能代替防转/防撞措施 |
