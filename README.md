## 启动

Windows x64 便携包已包含运行时和 Gateway 存根。解压后双击 `start_gui.bat`，现场操作见[首次上机指南](首次上机.md)。下面的 Python 安装和存根生成步骤适用于源码包。

安装含 Tcl/Tk 的 Windows Python 3.12。源码运行请先安装 `requirements-gateway.txt`；便携包已含依赖。双击 `start_gui.bat`，或执行 `python zen_gui.py`。也可通过环境变量 `ZEN_PYTHON` 指定 Python 可执行文件的完整路径。

选择「正常演示」运行四点采集。完成后可导出 JSON。选择「第 3 点 AF 超时演示」复核部分采集记录和启动锁定。使用「确认演示恢复」记录模拟确认，再启动下一轮。

数据保存在 `%LOCALAPPDATA%\ZENSurfaceTilt\demo` 下，每次运行单独建目录。运行目录含配方快照、逐点 CSV、日志和最终状态。有效运行另有结果 JSON。演示坐标用 m 存储，界面显示 µm。演示角度采用 Rx=atan(dZ/dY)、Ry=−atan(dZ/dX)，旧版约定待原工程核对。

## 资料与联调

现场入口依赖 `grpcio`、`protobuf` 和由蔡司 2026.11.1 proto 生成的 `zen_api` 存根。使用同一个 Python 执行以下命令。将路径替换为已取得的 [官方 2026.11.1 proto 目录](https://github.com/zeiss-microscopy/OAD/tree/master/ZEN-API/protofiles/proto_2026.11.1)。

```powershell
python -m pip install -r requirements-gateway.txt
python generate_gateway_stubs.py C:\path\to\proto_2026.11.1
$env:PYTHONPATH = (Resolve-Path .\gateway_stubs).Path
python zen_gui.py
```

同机默认配置可直接点击「Gateway 只读 XY」。工作台尝试 `127.0.0.1:5000`，读取 `%PROGRAMDATA%\Carl Zeiss\ZEN APIGateway` 下的默认 CA 与令牌。自定义配置可通过进程环境覆盖 `ZEN_GATEWAY_ADDRESS`、`ZEN_GATEWAY_CA`（PEM 证书路径）和 `ZEN_GATEWAY_TOKEN`。远程连接须显式配置对应的 CA 和令牌。参见[首次上机指南](首次上机.md)。

可先点击「新建／编辑配方」，再点击「编辑点位路径」，直接输入绝对 XY 坐标（µm）、修改或删除点位，并用上移／下移调整采集顺序。右侧预览显示点位编号与运动方向，编辑操作不会驱动设备。点击「应用路径」后，使用「保存现场配方」保存；取消编辑不改变原路径。至少三个非共线点才可批量测角，修改路径后须重新验证当前点 AF。CSV 导入作为可选方式保留。

按联调清单先执行「Gateway 只读 XY」。加载按 `recipe.example.json` 编辑的现场配方，然后示教或导入明确标有坐标单位的 CSV。示例点位仅展示文件格式。单点 AF 验证通过后，在设备端核对安全路径和间隙，再打开批量确认。批量配方需要明确采用临时联调约定 `联调约定：Rx=atan(dZ/dY)，Ry=-atan(dZ/dX)，角度单位 µrad`。正式约定待核对 V1.1。

运行回归测试使用 `python -B -m unittest -v test_zen_workflow`。

## 停止、退出与重启

「停止后续采集」会阻止开始后续点位，并等待当前调用返回。现场设备可能仍在运动或调焦。遇到紧急情况，按设备规程使用设备自身的急停与互锁。

任务运行期间关窗会请求停止后续采集。待状态栏显示本轮已结束或设备状态待确认后，再次关窗即可退出。强制退出或断电后，重新启动会扫描未完成的运行目录，现场待确认记录会锁住示教、单点 AF 和批量启动。

现场断线后可以重新连接读取 XY。解除待确认锁定前，请在设备端分别确认载物台 XY 与软件 AF/Z 已结束，再点击「确认现场恢复」，随后重新连接并做单点 AF 验证。XY 空闲只代表载物台状态。AF 超时后的 Z 行为仍待实机验证。

## 角度单位与状态栏

Rx、Ry 统一以微弧度（µrad，亦写作 urad）显示，计算为 `atan(斜率) × 10⁶`，不再输出度数。结果 JSON 使用 `rx_urad`、`ry_urad` 和 `angle_unit: "urad"`；历史结果文件保留原单位，不改写。采用旧版已知符号约定的配方载入时自动更新单位说明，点位与方向不变。RMS、PV 仍以 µm 显示。

顶部「真实设备」与「设备：未连接／就绪」说明连接状态；「离线演示」表示模拟数据。「演示与测试」菜单提供无需设备的演示入口，移除了无切换功能的「工程模式」字样。

## 当前点上下 mark 采图（V2.1）

点击右侧「上下 mark 采图」，可以在**当前同一个 XY** 分别拍摄上下两个焦面，保存 TIFF 后交给 SOMA 分析。本软件不识别 mark、不计算对位偏差，也不把这项采图加入 XY 批量路径。

1. 在 ZEN 中准备上、下两套已验证的拍摄实验，曝光和照明可以分别设置。两套实验须使用相同物镜、中间倍率、ROI 和像素标定；使用通道 0 的单张拍摄，不使用多维扫描或反射式 AF。
2. 连接现场 Gateway，在 ZEN 手动调清楚上 mark，点击上层「读取当前 Z」；再调清楚下 mark，读取下层 Z。界面输入单位为 µm，设备边界使用 m。两层必须已确认能用同一光路从同一侧分别看清。
3. 给两层分别填写局部 AF 半范围，两层搜索区间必须互不重叠。核对 Z 路径、物镜间隙和检查参数，选择输出目录，勾选确认。
4. 建议先用「仅拍上 mark」「仅拍下 mark」做现场验证，再「采集上下两张」。每层执行 Z 定位 → 到位回读及稳定等待 → 限定范围内 AF → 单张曝光 → TIFF 保存。软件不主动移动 XY，完成后停留在最后拍摄层的焦面，不自动返回。
5. 可以保存和加载独立的采图配置。参数改变或配置重新加载后，确认勾选会清除。现场 Z 和实验名不提供默认值。无设备时可「载入离线演示」，模拟图像存入带 `demo_` 前缀的目录，图像元数据也标记为模拟。

每轮在所选目录建立唯一的 `mark_<运行编号>` 文件夹，包含 `upper.tif`、`lower.tif` 和 `capture.json`。只拍一层时只产生对应的一张图，不能当作完整图片对。TIFF 支持原始 Gray8/Gray16 和 BGR24/BGR48（存为 TIFF 标准 RGB 通道顺序），不缩放、不增强、不降位深。像素尺寸同时写入标准 TIFF 分辨率标签和 JSON 描述，完整标定与实际 XYZ、实验、时间、镜头位置及完成状态保存在配套记录中。SOMA 是否自动读取标定须现场验证；若未读取，可按 `scale_x_m_per_pixel × 10⁶`、`scale_y_m_per_pixel × 10⁶` 输入 µm/pixel，不能把像素直接当成 µm。

该功能使用 Focus **v2** 的 `GetPosition/MoveTo`，不会回退到以 µm 为单位的 Focus v1；还需要 ObjectiveChanger v2、Optovar v2 的位置读取、ExperimentService 的临时克隆和 RunSnap，以及 ExperimentStreamingService 的完整原始帧。缺少选配服务时会提示，原有角度扫描仍可独立使用。AF 范围在临时实验上设置并回读校验，原实验不保存覆盖；曝光使用另一独立临时实验，避免误取 AF 的旧帧。ZEN 自身可能另存原始采集文件，软件的 TIFF 直接写入所选的本机目录。

异常时不自动重拍、不自动返回 Z。上层成功而下层失败时保留上图，整组标记为未完成。运行状态同时保存在现有 `ZENSurfaceTilt` 记录目录，重连或重启后仍会锁定新的采图和角度扫描，直到操作员确认 XY、Z、AF 和拍摄均已结束并记录恢复。软件停止不是硬件急停。

此版本已加入模拟和本地 gRPC 验证；真实服务的流订阅时序、两层 AF 搜索行为、Z 到位后的成像质量和 SOMA 导入标定仍须按实机清单验证。

## 无电动 XY 与共聚焦采集（V2.2）

适用于只有电动 Z、没有电动 XY 载物台的设备。在主界面「设备连接」选择 **无电动 XY · 仅单点采图**，再填写托盘实际 Gateway 地址（例如 `localhost:5002`，不是内部 ZEN 服务的 5024/5025）。切换模式会断开旧连接，需要重新连接。此模式只读 Z 验证 TLS/令牌，开机检查的 XY 状态和角度配方显示「不适用」；禁用真实角度扫描、角度单点 AF 和 XY 示教。软件不读、不写、不查询 XY 状态，也不能发现手动移动样品造成的水平偏移，必须手动固定样品。

打开「上下 mark 采图」后选择采集方式：

- **共聚焦采集（ZEN 采集实验）**：使用你在 ZEN **采集页**验证过的共聚焦实验，执行 `ExperimentService.RunExperiment`，不调用相机定位用的 `RunSnap`。须为单通道（通道 0）、单 Z 层、单时间点、无场景/拼图的一幅图像；结束后核对实验状态与完整帧，发现多维采集就拒绝保存。没有采集接口时提示失败，不回退相机拍照。
- **相机拍照（ZEN 定位 / Snap）**：明确选择此项才走 `RunSnap`，不能用它代替共聚焦结果。

初次验证可取消「定位后执行局部 AF」，先只读并示教当前 Z，使用「仅拍上 mark」验证 Z 定位和共聚焦图像保存；此时不调用 AF 参数接口或自动找焦。确认 AF 服务可用后再启用局部 AF、示教两层并进行成对采集。扫描速度、平均次数等沿用所选 ZEN 实验，默认界面拍摄超时为 60 秒，必要时按实际扫描时长增加。必须确认实验没有自带改变 XY、Z、物镜等位置的动作，不能把 Z-stack 实验直接当单平面采集使用。

无 XY 图像的 `frame_xyz_m` 前两项与运行起点均为 `null`，`xy_verified` 为 `false`，不会伪造 `(0,0)`。原始帧若不带 Z，则仅在无 XY 模式使用采集后的 Focus v2 位置回读，并将 `z_source` 标为 `focus_readback_after_capture`；采集前后的 Z 仍会检查。固定镜头设备若明确不提供物镜转盘/Optovar 的位置方法，可在此模式记录为未校验并由操作员手动确认镜头、倍率不变；认证失败或其他接口错误不会作为“不适用”忽略。有电动 XY 模式仍保留严格的位置与镜头检查。

旧采图配置默认按有 XY、相机 Snap 和局部 AF 解释；新版保存模式与采集方式，载入不同 XY 模式的配置后需要重新连接。所有异常恢复锁定仍有效。实际共聚焦图像流的完整帧组装、AF 行为及 SOMA 导入仍需在现场验证。


## ZEN 3.12 现场诊断与自动记忆（V2.3）

ZEN 界面版本和 Gateway 版本不能证明某个 API 方法已实现；本版记录操作员填写的 ZEN 版本（默认 3.12），不据此自动切换 API，也不宣称已通过真实 ZEN 3.12 验收。

采图窗口新增「只读检查实验名（不加载）」。此操作仅调用实验名称列表与当前位置读取，不执行 Load、Clone、AF、MoveTo 或拍摄。可以在已有恢复锁定时做只读检查，不会清除锁定。列表方法不支持时标为未知，不把它误报为实验不存在。公开列表只提供名称，不能在不加载实验的前提下完整获取曝光、转盘或位置恢复参数；列表通过也不代表采集或转盘安全。

采图失败现在明确显示完整服务/方法名和 gRPC 状态码，例如 `zen_api.acquisition.v1beta.ExperimentService.Clone → UNIMPLEMENTED`。`capture.json` 包含结构化 `error` 和最多 256 条方法级 `rpc_trace`，窗口也可保存诊断报告。只记录方法、时间、状态码与本软件提示，不复制请求体、控制令牌、认证头或服务端原始错误详情。`NOT_FOUND` 与 `UNIMPLEMENTED` 分开解释。

新增独立的“已在 ZEN 核对实验加载/运行不会换物镜或恢复位置”人工确认；未确认时不加载、不拍摄。这不是转盘锁定。软件没有建立硬件防转保护；只能读到 Z，或转盘位置接口不可读时，不能据此保证换物镜不会发生。未排除撞机风险时，仅做只读检查，不应通过反复试拍排查兼容性。

采图实验名、示教 Z/AF 参数、采集方式、输出目录、是否使用 AF、XY 模式和人工记录的 ZEN 版本会自动保存到 `%LOCALAPPDATA%\ZENSurfaceTilt\preferences\ui.json`。支持恢复尚未填写完整的编辑内容，但不会因此绕过参数校验。Gateway 地址与 CA 路径在应用连接设置时记住；控制令牌不保存。仍保留手动配置文件的导入/导出，便于分享或备份。

下次打开自动恢复参数，但不自动连接或动作。历史 Z 值不是本次位置读取，两项安全确认都重新置空；演示配置来源标记保留，不能直接用于实机。损坏的自动配置文件不会被悄悄覆盖，界面会提示仍可手动填写。

### 硬件库 · 通信与单步测试（2.4）

主窗口点击 **硬件库 · 通信与单步测试**。此窗口用于逐项验证设备接口，不运行测角或上下 mark 流程。打开窗口及恢复参数不会发送指令。

1. 在主窗口选择有 XY / 无 XY，填写连接设置，再进入测试窗口并“绑定现场设备”。绑定不连接；选择“连接通信”并执行，才建立 TLS 通道。连接成功不证明认证或位置接口可用。
2. 先分别测试读取 Z、读取转盘/倍率位置、列出实验；无 XY 模式禁止 XY 请求。
3. 如需加载实验，先在 ZEN 检查物镜、硬件设置及安全范围。选中 Load，填写准确实验名，勾选本次确认后执行。返回的实验 ID 自动填入本次窗口的实验参数，ID 不跨连接保存。
4. 对可能运动的操作，接口返回后须先在设备端确认运动、AF、采集结束，再点击“确认设备恢复”。日志保留待确认状态；只读查询及 Stop 请求仍可使用。Stop 不能替代硬件急停，超时也不代表设备停止。
5. AF、Z MoveTo、SNAP、RunExperiment 都是独立操作；不会隐式 Clone、改范围或追加拍照。设置 AF 范围先读再写；设置曝光先读取相机并保留 binning/ROI。Z-stack 设置只修改范围，不启用维度或扫描，执行请用 RunExperiment。

目标位置/AF 范围/Z-stack 输入单位为 **µm**，内部转换为 API 的 **m**；返回 JSON 使用 API 原始字段（Z-stack 长度为 m）。相机接口未标注曝光单位，因此显示 **API 原始单位**，须根据当前相机返回范围及 ZEN 核对，不能直接当成毫秒。相机曝光不等于共聚焦扫描驻留时间/激光功率。

SNAP 用相机；共聚焦/Z-stack 用 RunExperiment，遵循 ZEN 中当前实验配置。单步测试不接收像素流或自动导出 TIFF；文件由 ZEN 保存，可独立查询保存目录与实验状态。正式 mark 流程仍有自己的图像保存机制。

测试窗口不提供物镜转盘运动命令；**Load 或运行实验仍可能应用物镜设置**，读到物镜位置不代表已经锁定。写入/动作确认每次执行后重置。

每个会话自动生成 `hardware_logs/<会话ID>/session.jsonl` 和 `session.log`，包含操作/参数与单位标签、开始结束时间、耗时、返回值、RPC 方法/状态及客户端调用位置。验证失败也记录；控制令牌、请求认证元数据、原始实验 XML 和图像字节不写入共享日志。可复制本次结果/全部日志，或导出日志发给开发者。设备返回的名称、路径仍可能包含现场信息，分享前可自行检查。输入参数会自动记住，实验 ID、令牌及动作确认不保存。

可复用的库入口：`zen_hardware.library.HardwareTestSession`（日志、校验、串行与恢复记录）和 `HardwareLibrary`（设备操作适配）；Tk 界面只调用 Workflow 派发，不直接调用 gRPC。新增设备可实现 `connect_transport`、`close`、`call_hardware_operation`；真实 Gateway 的接口实现位于 `zen_hardware/controls.py`。
